Context engine

Your codebase, in working memory

Large codebases don't fit in one pass — so SteinzSAST chunks code along semantic boundaries and assembles exactly the context each finding needs: the AST around it, the call paths into it, and the data flows through it.

  • Semantic code chunking that respects function and module boundaries
  • AST-level structure for precise, language-aware matching
  • Call-graph context across files and services
  • Taint propagation from untrusted sources to dangerous sinks

LLM-assisted triage

Every finding gets a reviewer

Each candidate finding goes to an LLM reviewer with the full assembled context. The verdict comes back with reasoning: is it reachable, is it exploitable, what's the fix. False positives are suppressed — with the reason on record, not silently dropped.

  • True/false positive verdicts with written rationale
  • Exploitability and reachability assessment per finding
  • Suggested remediation in the code's own idiom
  • Suppressions you can audit and overturn

The classes that cause breaches

⌁

Injection

SQL, command, and template injection traced from input to execution — with the sanitization gaps named.

⇢

Path traversal & SSRF

User-controlled paths and URLs followed through joins, builders, and HTTP clients.

⬢

Unsafe deserialization

Untrusted data reaching deserializers, object loaders, and dynamic evaluation.

⚿

Broken authorization

Missing and inconsistent access checks across routes, handlers, and service boundaries.

∗

Secrets & crypto misuse

Hardcoded credentials, weak primitives, and keys in places they shouldn't be.

≋

Data exposure

Sensitive fields flowing into logs, responses, and third-party calls without controls.
